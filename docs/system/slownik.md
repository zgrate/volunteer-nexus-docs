# Słownik pojęć

Jedno słowo na jedną rzecz: pojęcia z tej strony obowiązują w całej dokumentacji.

Słownik ma trzy części: pojęcia opisujące wydarzenie i wolontariuszy, które istnieją niezależnie od systemu, pojęcia systemowe, czyli nazwy elementów Volunteer Nexus, oraz pojęcia techniczne, używane w dokumentacji technicznej. Puste pole w kolumnie „Definicja” oznacza, że definicja nie została jeszcze ustalona.

## Wydarzenie i wolontariusze

| Pojęcie | Definicja |
| --- | --- |
| Organizacja | Podmiot organizujący wydarzenia. Ma stałych członków, niezależnie od pojedynczych wydarzeń. |
| Wydarzenie | Wydarzenie, zwana także konwentem, to impreza organizowana przez organizacje. Wydarzenie posiada wolontariuszy oraz pion organizacji. Wydarzenie odbywa się w konkretnych datach i lokalizacji. Dzieli się na fazę przed konwentem - planowanie, faze w trakcie wydarzenia, oraz fazę po konwencie - zbieranie wniosków i przygotowanie do nowego cyklu |
| Wolontariusz | Osoba pomagająca przy organizacji oraz przebiegu wydarzenia, posiadająca podpisaną umowę o wolontariat, przydzielone benefity, zmiany oraz inne elementy potrzebne do przeprowadzenia wydarzenia |
| Stały członek organizacji | Wolontariusz związany z organizacją na stałe, a nie tylko z jednym wydarzeniem. Osoba oznacza się tak sama; osoba, której rola na to pozwala, może to oznaczenie nadpisać. |
| Organizator | Osoba odpowiedzialna za wydarzenie. Zarządza wolontariuszami i działami, w których jest członkiem. Wydarzenie może mieć wielu organizatorów. |
| Administrator | Osoba zarządzająca systemem: ustawia wydarzenia, role i uprawnienia, wyłącza i włącza konta, zmienia adres e-mail konta. |
| Koordynator | Osoba zajmująca się działem. Dział może mieć wielu koordynatorów. |
| Lider | Szef zespołu. Współpracuje z koordynatorem i organizatorem. Zespół może mieć wielu liderów. |
| Dział, sekcja | Najwyższa jednostka podziału wolontariuszy na wydarzeniu - dział zajmuje się konkretnym dużym wycinkiem wydarzenia. Działem zajmują się koordynatorzy, a odpowiadają za niego organizatorzy. |
| Zespół | Grupa wolontariuszy pracująca w danym dziale nad mniejszym wycinkiem wydarzenia. Szefem zespołu jest lider, który współpracuje z koordynatorem oraz organizatorem w celu organizacji wycinka; zespół może mieć wielu liderów. |
| Członkostwo w dziale | Wolontariusz przypisany do działu jest "członkiem działu". Jeden dział posiada wielu wolontariuszy współpracujących razem. |
| Członkostwo w zespole | Przypisanie członka działu do zespołu tego działu. Osoba może należeć do kilku zespołów albo do żadnego; nie można należeć do zespołu bez członkostwa w jego dziale. |
| Oznaczenie w dziale | Informacja, czym osoba zajmuje się w dziale lub zespole: organizator, koordynator, lider albo członek. Samo oznaczenie nie daje uprawnień – te daje rola. |
| Osoba kontaktowa | Organizator albo koordynator działu, który udostępnił swoje dane kontaktowe. Widać go w formularzu aplikacji, żeby osoba mogła skontaktować się z działem przed aplikacją. |
| Usunięcie z działu | Zakończenie członkostwa osoby w dziale i we wszystkich jego zespołach. Wymaga podania powodu. Nie kończy uczestnictwa w wydarzeniu. |
| Usunięcie z wydarzenia | Zakończenie uczestnictwa osoby w wydarzeniu i wszystkich jej członkostw w działach tego wydarzenia. Nie wyłącza konta. |
| Dział główny | Dział, który osoba ustawia na pierwszym miejscu, gdy aplikuje do więcej niż jednego działu. Ma pierwszeństwo w decyzji: aplikacje do pozostałych działów wymagają także jego zgody. Gdy dział główny odrzuci aplikację albo osoba ją wycofa, działem głównym staje się następny dział w kolejności. |
| Aplikacja Wolontariacka | Zgłoszenie osoby, która chce zostać wolontariuszem w dziale lub zespole. Wymaga akceptacji. Zgłoszenie posiada różne elementy, zależne od działu, do którego aplikuje wolontariusz |
| Stan aplikacji | Etap, na którym jest aplikacja wolontariacka: oczekująca, wycofana, zaakceptowana albo odrzucona. Rozpatrujący widzi dodatkowo stan „Czeka na dział główny”. |
| Rozpatrujący | Osoba, której rola pozwala podjąć decyzję o aplikacji wolontariackiej: zaakceptować ją albo odrzucić. |
| Powód odrzucenia | Uzasadnienie, które rozpatrujący musi podać przy odrzuceniu aplikacji wolontariackiej. Osoba aplikująca je widzi. |
| Notatka wewnętrzna | Uwaga do aplikacji wolontariackiej widoczna tylko dla osób, które mogą przeglądać aplikacje. Osoba aplikująca jej nie widzi. |
| Lista osób z zakazem wolontariatu | Lista osób, których nie należy przyjmować na wolontariuszy. Aplikacja takiej osoby pokazuje ostrzeżenie, a przyjęcie wymaga osobnego potwierdzenia. |
| Uczestnictwo | Uczestnictwo w wydarzeniu - Gdy wolontariusz uczestniczy w wydarzeniu oznacza, że pomaga w wydarzeniu |
| Historia uczestnictwa | Informacja o tym, w których wydarzeniach i w jakiej roli wolontariusz brał udział. Pozwala rozpoznać osoby powracające co roku. |
| Zmiana | Odcinek pracy wolontariuszy na wydarzeniu: ma początek, czas trwania i może mieć lokalizację. Składa się ze stanowisk. Jest otwarta albo zamknięta. |
| Stanowisko | Rola do obsadzenia na zmianie. Ma nazwę i określoną liczbę miejsc, może należeć do działu i zespołu. Wolontariusza przydziela się do stanowiska, nie do zmiany wprost. |
| Przydział | Przypisanie wolontariusza do stanowiska na zmianie. Powstaje, gdy przydzieli go osoba zarządzająca zmianami, gdy wolontariusz zapisze się sam albo gdy system utworzy zmianę z siatki godzin. |
| Obsada | Osoby przydzielone w danym czasie do stanowiska lub kategorii służby, porównywane z liczbą osób potrzebnych. |
| Zastępstwo | Przydział, który zastępuje wcześniejszy przydział innej osoby na tym samym stanowisku. |
| Obecność | Informacja, czy wolontariusz stawił się na zmianie. Obecność nie tworzy przepracowanych godzin. |
| Zadanie | Praca do wykonania w trakcie zmiany, przydzielana osobie obsadzonej na stanowisku. Część zadań pochodzi ze zgłoszeń dyspozytorskich. |
| Lokalizacja | Miejsce na wydarzeniu, w którym odbywa się zmiana, np. scena lub rejestracja. Zmiana może nie mieć lokalizacji. |
| Niedyspozycyjność | Okres, w którym wolontariusz zgłosił, że nie może pracować. Pełna blokuje przydział w tym czasie, warunkowa tylko ostrzega planującego. Zgłoszenie działa od razu; organizator może je odrzucić, podając powód. |
| Operator zmian | Osoba, która planuje zmiany działu: tworzy zmiany, wypełnia siatkę godzin i ustawia reguły. |
| Przyjazd i wyjazd | |
| Godziny zaplanowane | Suma czasu trwania zmian, do których wolontariusz jest przydzielony. System porównuje je z godzinami zadeklarowanymi i ostrzega przy przekroczeniu. |
| Przepracowane godziny | |
| Zadeklarowane godziny | Godziny, które osoba deklaruje w aplikacji wolontariackiej osobno dla każdego działu, w podziale na czas przed wydarzeniem, w jego trakcie i po nim. Po akceptacji aplikacji zmienia je tylko organizator. |
| Dyspozytor | |
| Zgłoszenie | |
| Umowa | Umowa wolontariacka (umowa o wolontariat) podpisywana przez wolontariusza. Istotne jest, kto ją podpisał, czy została zweryfikowana i kiedy wygasa. |
| Umowa na czas nieokreślony | Umowa bez daty wygaśnięcia. Dopóki jest ważna, system nie wyłącza osoby w wydarzeniu. |
| Zgoda RODO | |
| Zgoda na dłuższe przetwarzanie danych | Zgoda osoby na to, żeby system przechowywał jej dane także wtedy, gdy nie jest w żadnym wydarzeniu. Chroni konto przed wyłączeniem przez system. |
| Anonimizacja | Usunięcie z systemu danych, które pozwalają rozpoznać osobę. Wyłącza konto osoby i usuwa jej aplikacje. |
| Benefit | Korzyść przysługująca wolontariuszowi. To, które benefity przysługują, zależy od warunków, np. liczby wydarzeń lub przepracowanych godzin. |
| Poziom benefitów | Jeden z poziomów zdefiniowanych z góry dla wydarzenia. Osoba wybiera go w aplikacji wolontariackiej, gdy wydarzenie korzysta z poziomów zamiast z karty godzin; wybrany poziom jest przypisany do konkretnej aplikacji. |
| Dostęp | Uprawnienie wolontariusza do systemu, konta lub kanału komunikacji. Organizatorzy muszą wiedzieć, kto je ma i komu należy je odebrać. |

## Pojęcia systemowe

| Pojęcie | Definicja |
| --- | --- |
| Volunteer Nexus | Nazwa systemu. Jeden system, w którym wolontariusz sam sprawdza swoje sprawy, a organizatorzy zarządzają wszystkimi wolontariuszami na wydarzeniu i w organizacji. |
| MVP | Wersja systemu, której celem jest doprowadzenie obecnego systemu do stanu stabilnego. |
| Konto | Zapis osoby w systemie, jeden dla wszystkich wydarzeń, rozpoznawany po adresie e-mail. Konto pozwala się zalogować; dostęp do spraw wydarzenia daje dopiero uczestnictwo. |
| Konto nieaktywne | Konto, które nie pozwala korzystać z systemu. Wyłącza je administrator albo system. |
| Wyłączenie w wydarzeniu | Stan, w którym osoba traci dostęp do spraw jednego wydarzenia, ale nadal może się zalogować i korzystać z innych wydarzeń. |
| Kod logowania | Jednorazowy kod, którym osoba loguje się zamiast hasłem. System wysyła go kanałem powiadomień wybranym przez osobę. Jest ważny 15 minut. |
| Sesja | Zalogowanie osoby na jednym urządzeniu. Odnawia się, gdy osoba korzysta z systemu, i wygasa po 30 dniach bez użycia. |
| Profil | Dane osoby w systemie: dane podstawowe, wspólne dla konta, oraz odpowiedzi na pola niestandardowe, osobne dla każdego wydarzenia. |
| Dane podstawowe | Dane osoby wspólne dla konta: imię i nazwisko, nickname, adres e-mail, kontakt na Telegramie oraz pola systemowe. Osoba wpisuje je raz; później zmienia je organizator. |
| Pole systemowe | Pole niestandardowe wspólne dla konta, a nie dla jednego wydarzenia, np. PESEL. Rozszerza dane podstawowe. |
| Zdjęcie profilowe | Zdjęcie osoby widoczne dla zalogowanych wolontariuszy wydarzenia. |
| Lista kontrolna | Lista kroków, które osoba musi wykonać przed wydarzeniem, z informacją, ile już wykonała. Wydarzenie wybiera, których kroków używa. |
| Dane kontaktowe | Dane, którymi można skontaktować się z osobą: adres e-mail konta, kontakt na Telegramie i numer telefonu. Adres e-mail i kontakt na Telegramie są wymagane, numer telefonu nie. |
| Kontakt na Telegramie | Nazwa użytkownika osoby na Telegramie albo konto połączone z Telegramem. Dopiero połączenie konta pozwala systemowi wysyłać osobie wiadomości na Telegramie. |
| Udostępnianie kontaktu | Ustawienie w profilu, którym osoba decyduje, czy inni wolontariusze wydarzenia widzą jej adres e-mail, kontakt na Telegramie i numer telefonu – każde osobno. Domyślnie wyłączone. |
| Ustawienia lokalizacyjne | Sposób zapisu danych zależnych od kraju, np. format daty. Osoba ustawia je w profilu obok języka. |
| Identyfikator Foxcons | Numer, który łączy osobę z jej rejestracją w Foxcons. Jest przypisany do wydarzenia. |
| Nickname | Nazwa, pod którą osoba jest znana na wydarzeniu. Osoba podaje ją obok imienia i nazwiska. |
| Rola | Zestaw uprawnień nadawany osobie. |
| Uprawnienie | Pozwolenie na konkretną czynność w systemie, np. przeglądanie aplikacji albo decyzję w dziale. Nie mylić z dostępem. |
| Kanał powiadomień | Droga, którą system wysyła osobie wiadomości: e-mail albo Telegram. Osoba wybiera kanał w profilu. Gdy wiadomości nie da się dostarczyć wybranym kanałem, system wysyła ją e-mailem. |
| Powiadomienie | Wiadomość, którą system wysyła osobie, np. o przydziale do zmiany albo o decyzji w sprawie aplikacji. Ma tytuł adekwatny do treści. |
| Rodzaj powiadomień | Grupa powiadomień o tej samej sprawie, np. przydział do zmiany. Osoba wybiera, które rodzaje chce dostawać; części rodzajów nie może wyłączyć. |
| Skrzynka powiadomień | Miejsce w systemie, w którym osoba widzi wiadomości wysłane do niej wszystkimi kanałami, także te niedostarczone. Wiadomości są przechowywane 365 dni; osoba może wcześniej usunąć wybrane. |
| Przypomnienie o zmianie | Powiadomienie wysyłane osobie przed zmianą, do której jest przydzielona. Osoba ustawia, ile czasu przed zmianą je dostaje; domyślnie godzinę przed, kwadrans przed i w chwili rozpoczęcia. |
| Kod potwierdzający | Jednorazowy kod, którym osoba bez konta potwierdza adres e-mail w aplikacji wolontariackiej. Przychodzi zawsze e-mailem i nie loguje osoby. |
| Mailer | Miejsce w systemie, z którego organizator wysyła wiadomość do wybranych osób, do członków działu albo do wszystkich uczestników wydarzenia. |
| Panel administracyjny | Nie mylić z Django Admin. |
| Centrum informacji | Miejsce w systemie z dokumentacją i informacjami ważnymi dla wolontariuszy. Wyświetlana publicznie dla wszystkich wolontariuszy, albo ograniczona do konkretnych działów |
| Grupa dostępu | Zestaw działów, zespołów i wolontariuszy, którzy mogą wchodzić do tych samych stref wydarzenia. Odpowiada karcie dostępu w Foxcons. |
| Pole niestandardowe | Pytanie, na które osoba odpowiada w aplikacji wolontariackiej i w profilu. Pole przypisane do wydarzenia może dotyczyć całego wydarzenia, wybranych działów albo wybranych zespołów; pole systemowe jest wspólne dla konta. |
| Pole wrażliwe | Pole niestandardowe, którego odpowiedzi widzi tylko osoba z uprawnieniami do przeglądania aplikacji i do wglądu w dane wrażliwe. |
| Notatka | |
| Karta Godzin | |
| Tryb planowania | Sposób planowania zmian ustawiany dla działu: tryb standardowy albo siatka godzin. |
| Tryb standardowy | Tryb planowania, w którym organizator tworzy każdą zmianę osobno i opisuje jej stanowiska. |
| Siatka godzin | Tryb planowania dla działów pracujących w trybie ciągłym. Wiersze to wolontariusze działu, kolumny to odcinki po 30 minut; operator zmian zaznacza, kto w którym odcinku pełni jaką służbę, a system sam składa z tego zmiany. W interfejsie: „Siatka planowania ciągłego”. |
| Odcinek | Półgodzinna kolumna siatki godzin. |
| Kategoria służby | Rodzaj służby wpisywany w komórki siatki godzin, np. patrol lub posterunek. Ma kod, nazwę i kolor, może mieć lokalizację, zespół i regułę. Z kategorii powstaje nazwa stanowiska. W interfejsie: „kategoria dyżuru”. |
| Blokada | Kategoria służby, która nie tworzy zmiany, tylko niedyspozycyjność wolontariusza, np. przerwa. |
| Wymaganie obsady | Liczba osób, których dział potrzebuje w każdej kategorii służby – domyślnie albo w wybranym oknie czasu. Siatka pokazuje braki, ale ich nie blokuje. |
| Adnotacja | Opisany odcinek czasu wyświetlany nad siatką godzin lub pod nią, np. punkt programu, o którym planujący ma pamiętać. |
| Szablon zmiany | Wzór zmiany ze stanowiskami i zadaniami, z którego tworzy się nowe zmiany w trybie standardowym. |
| Reguła | Warunek ustawiany przez organizatorów, który wolontariusz musi spełnić, żeby objąć stanowisko: rejestracja na wydarzenie, wartość pola w profilu albo przynależność do działu lub zespołu. Reguły łączy się w szablony reguł. |
| Sprawdzenie stałe | Warunek przydziału, który system sprawdza zawsze: wolne miejsca, przynależność do działu i zespołu stanowiska, kolizja z inną zmianą, kolizja z prowadzonym punktem programu, niedyspozycyjność. |
| Pominięcie warunku | Świadomy przydział mimo niespełnionego warunku, wykonany przez osobę zarządzającą zmianami działu. System zapisuje, co zostało pominięte. |
| Samodzielny zapis | Przydział, który wolontariusz tworzy sam na stanowisku, które na to pozwala. Wymaga otwartej zmiany, przynależności do działu stanowiska i terminu zapisów, który nie minął; nie może pominąć żadnego warunku. |
| Okno planowania zmian | Zakres dni wokół wydarzenia, w którym można planować zmiany. |
| Ekran Conops | Ekran pokazujący bieżące i nadchodzące zmiany wybranych działów lub lokalizacji, wyświetlany na osobnym urządzeniu. |
| Grupa umów | |
| Szablon dokumentu | |
| Wygenerowany dokument | |
| Dziennik audytu | Zapis tego, kto i kiedy zmienił dane lub podjął decyzję. |
| Foxcons | Osobny system organizacji, który obsługuje rejestrację uczestników wydarzeń, przydzielanie pokojów i płatności. Volunteer Nexus wymienia z nim dane o wolontariuszach. |
| Harmonogram Foxcons | Sale i punkty programu wydarzenia pobierane z Foxcons. |
| Punkt programu | Pozycja harmonogramu wydarzenia pobrana z Foxcons, np. prelekcja lub panel. Wolontariusz, który prowadzi punkt programu, nie może mieć w tym czasie przydziału. |
| Stanowisko rejestracji | Lokalna aplikacja na komputerze przy rejestracji wydarzenia, na której obsługa generuje, drukuje i przyjmuje podpisane umowy. Kod: katalog `counter/`. |

## Pojęcia techniczne

Pojęcia używane w dokumentacji technicznej.

| Pojęcie | Definicja |
| --- | --- |
| v1 | Wersja systemu rozwijana od kwietnia do listopada 2026 r. Dział „v1” opisuje stan systemu z listopada 2026 r. |
| Interfejs | Część systemu działająca w przeglądarce użytkownika. Jedna aplikacja wspólna dla wolontariuszy, organizatorów i administratorów. |
| Serwer | Część systemu, która przechowuje dane i udostępnia je interfejsowi przez API. |
| API | Zestaw adresów pod ścieżką `/api/`, przez które interfejs, urządzenia i integracje komunikują się z serwerem. |
| Usługa | Osobno uruchamiany kontener systemu, np. serwer, baza danych, kolejka zadań. |
| Aplikacja | Moduł serwera odpowiadający za jeden obszar, np. zmiany lub umowy. Nie mylić z aplikacją wolontariacką. |
| Zadanie w tle | Czynność wykonywana przez serwer poza obsługą żądania, bo trwa długo albo ma się powtarzać, np. generowanie dokumentu lub wysyłka przypomnień. Nie mylić z zadaniem na zmianie. |
| Klucz API | Sekret, którym urządzenie lub integracja uwierzytelnia się wobec serwera zamiast logowania użytkownika. |
| Dostawca logowania | Zewnętrzna usługa, która potwierdza tożsamość użytkownika przy logowaniu. System korzysta z dwóch: authentik oraz Login Hub. |
| Login Hub | Dostawca logowania, który pozwala zalogować się do systemu kontem Foxcons. |
| Plik prywatny | Plik dostępny tylko po sprawdzeniu uprawnień przez serwer, np. skan umowy lub wygenerowany dokument. |
| Historia zmian | Kopie poprzednich wersji najważniejszych danych, zapisywane przy każdej zmianie. Nie mylić ze zmianą jako odcinkiem pracy. |
| Aplikacja PWA | Interfejs zainstalowany na urządzeniu i uruchamiany jak osobny program. Pokazuje zapisane dane, gdy serwer nie odpowiada, i odbiera powiadomienia. |
| Powiadomienie na urządzenie | Powiadomienie wyświetlane na telefonie lub komputerze wolontariusza także wtedy, gdy aplikacja jest zamknięta. Działa w przeglądarce i w aplikacji PWA; osoba włącza je na każdym urządzeniu osobno. |
| Kopia zapasowa | Archiwum ze zrzutem bazy danych oraz plikami publicznymi i prywatnymi, tworzone codziennie. |
